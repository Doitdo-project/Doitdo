
## 7. 상태 전이 + 라벨/컴포넌트

### 상태 enum

조회된 이슈의 상태값:
- `해야 할 일` (= To Do)
- `진행 중` (= In Progress)
- `완료` (= Done)

**주목**: 완료 상태 JQL에서 `status = 완료`는 0건, `status = Done`은 15건 반환됨.
→ 실제 JIRA 내부 상태 값은 `Done`(영문), UI 표시는 `완료`(한글) 이원화.
→ JQL 작성 시 반드시 `status = Done` 사용 필요.

ssafy-example.md의 상태 흐름(`To Do → In Progress → Code Review → Done`)과 달리, 이 프로젝트는 **Code Review 상태가 없음** — 3단계 심플 워크플로우:
```
해야 할 일 → 진행 중 → Done(완료)
```

### 전이 규칙

- 스토리: 모든 하위작업 완료 시 스토리 완료로 전환 (메모리 기록)
- 현재 상태 분포 (본인 담당 36건):
  - 완료: ~22건 (약 61%)
  - 해야 할 일: ~12건 (약 33%)
  - 진행 중: ~2건 (약 6%)

### 라벨·컴포넌트

모든 조회 이슈에서 라벨 미사용 확인. 컴포넌트도 CLI 출력 미표시 + 노션 컨벤션 미언급으로 미사용 추정.

## 10. 노션 SSOT vs 실제 사용 — 불일치/모호 영역 (사용자 확정 필요)

### 불일치 1: Story 마침표 여부

노션 SSOT: `사용자는 ~ 하고 싶다 형식으로 작성` — 마침표 명시 없음.
실제 사용: 초기 이슈(32, 34, 98~102)는 마침표 있음, 최근 이슈(345, 346, 300~306)는 없음.
**확정 필요**: 마침표를 붙이는 것이 표준인가?

### 불일치 2: Task vs Sub-task 경계 모호

노션 SSOT: Sub-task = API 단위.
실제 사용:
- `S14P31D107-332`([BE] Feat: T13 카테고리 조회 API)는 **Task(작업)** 유형인데 내용은 API 단위
- `S14P31D107-355`(Feat: FCM 디바이스 토큰 해제 API)도 **Task(작업)** 유형
→ 김재환이 CLI로 생성한 API 단위 이슈가 Sub-task가 아닌 Task로 들어간 경우 있음
**확정 필요**: API 단위 이슈는 반드시 Sub-task여야 하는가, Task도 허용하는가?

### 불일치 3: Task 제목에서 `[파트]` prefix 누락

노션 SSOT: 작업·하위 작업 서두에 `[BE]`, `[FE]` 등 필수.
실제 사용: `S14P31D107-355`, `S14P31D107-356`은 `[BE]` 없이 `Feat:`, `Refactor:` 바로 시작.
**확정 필요**: `[파트]` prefix 는 Task에도 예외 없이 필수인가?

### 불일치 4: Story 예외 — "하고 싶다" 대신 다른 서술

`S14P31D107-308`: `사용자는 TODO 완료 시 다마고치가 경험치를 얻기를 원한다`
→ "~하고 싶다" 패턴이 아니라 "~를 원한다" 사용.
**확정 필요**: "사용자는 ~하고 싶다"가 절대 규칙인가, 서술형이면 OK인가?

### 불일치 5: 알림 에픽 부재

알림 관련 스토리(S14P31D107-345 받은 알림 관리, S14P31D107-346 저녁 리마인더)는 별도 에픽 없이 독립 존재.
노션 컨벤션은 "에픽 = 도메인 단위"라 명시했지만 알림 도메인 에픽이 없음.
**확인 필요**: 알림 기능은 TODO/설정 에픽 하위인가, 별도 에픽이 필요한가?

### 불일치 6: Story 유형인데 `[DOCS]` prefix + "사용자는 ~" 패턴 이중 위반

노션 SSOT: 스토리는 "사용자는 ~하고 싶다" 서술형, prefix(`[파트]`) 금지.
노션 SSOT: `[DOCS]` prefix는 Task/Sub-task 전용.

실제 수집 이슈:
- `S14P31D107-9`: `[DOCS] 와이어 프레임 설계` — **이슈 유형 = 스토리**, `[DOCS]` prefix 사용, "사용자는 ~" 서술형 아님 → **이중 위반**
- `S14P31D107-11`: `[DOCS] ERD 설계 및 작성` — **이슈 유형 = 스토리**, `[DOCS]` prefix 사용, "사용자는 ~" 서술형 아님 → **이중 위반**

추정 원인: 프로젝트 초기(번호 9, 11)에 이슈 유형·제목 컨벤션이 정착되기 전에 생성된 레거시 이슈. 이후 팀 컨벤션이 노션에 정착되면서 이런 형식은 더 이상 사용하지 않음.
**확인 필요**: 초기 레거시 이슈 예외로 인정하는가, DOCS 성격 이슈는 스토리가 아닌 Task로 생성해야 하는가?
